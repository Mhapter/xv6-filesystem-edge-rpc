03 / Engineering walkthrough
How we implemented it
01 / kernel/fs.h
Change inode geometry
Replace one direct pointer with a double-indirect pointer. Both inode structures retain 13 address slots.
uint addrs[NDIRECT + 2];
02 / kernel/fs.c
Map blocks
In bmap(), subtract the direct and single-indirect ranges before calculating the two indices. Allocate missing blocks, log changes and release the root buffer before reading the leaf.
03 / kernel/fs.c
Reclaim storage
In itrunc(), free data blocks first, then second-level index blocks, then the root. Clear inode pointers and update the inode.
Interactive reclamation model
Illustrative one-branch tree; not a live kernel operation.

Ready: free the data block first.
Why not more pointers?
A second double-indirect pointer could replace another direct pointer while preserving inode size. A triple-indirect pointer would address more blocks but adds another lookup level and more reclamation complexity. Neither is implemented in this project.

Reproduction checklist
Obtain the original source tree and matching toolchain, check BSIZE and disk capacity, rebuild a disposable filesystem image, boot QEMU and run bigfile. Then test the original RPC service on a trusted local network.
docker build -t xv6-edge-rpc .
docker run --rm --memory=128m --cpus=.25 -p 127.0.0.1:8080:8080 xv6-edge-rpc
# Separate terminal:
docker stats --no-stream
# With original manifest and accessible image:
kubectl apply -f <original-manifest.yaml>
kubectl get pods,svc
Illustrative commands only; original source and manifests are required. Do not expose the unauthenticated RPC service publicly.
